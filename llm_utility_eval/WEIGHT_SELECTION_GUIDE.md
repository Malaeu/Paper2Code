# 🎯 Руководство по выбору весов для LLM Utility Function

## 📐 Формула
```
Utility = α × Quality + β × Speed + γ × Stability − δ × CostPenalty
```

## 🤔 Как были выбраны текущие веса?

### Default (Balanced): α=1.0, β=0.8, γ=1.0, δ=1.2
**Логика выбора:**
- Quality (1.0) - базовый вес, т.к. качество критично для большинства задач
- Speed (0.8) - немного ниже, т.к. разница 100ms vs 200ms часто не критична
- Stability (1.0) - равно качеству, т.к. сбои могут испортить UX
- Cost (1.2) - выше базового, т.к. цена часто ограничивающий фактор

### Quality First: α=1.5, β=0.5, γ=1.0, δ=0.8
**Логика выбора:**
- Quality (1.5) - увеличен на 50% для приоритета точности
- Speed (0.5) - снижен вдвое, скорость менее важна
- Stability (1.0) - стандарт, стабильность всегда важна
- Cost (0.8) - снижен, готовы платить за качество

### Speed Optimized: α=0.7, β=1.5, γ=0.8, δ=1.0
**Логика выбора:**
- Quality (0.7) - снижен, но не слишком (качество все еще важно)
- Speed (1.5) - увеличен на 50% для real-time приложений
- Stability (0.8) - немного снижен (можем retry при сбоях)
- Cost (1.0) - стандарт

### Budget Conscious: α=0.9, β=0.9, γ=0.9, δ=2.0
**Логика выбора:**
- Quality/Speed/Stability (0.9) - все немного снижены
- Cost (2.0) - удвоен для максимальной экономии

## 📊 Методика правильного выбора весов

### 1. Анализ требований
Ответьте на вопросы:
- Насколько критична точность? (влияет на α)
- Нужен real-time отклик? (влияет на β)
- Можно ли повторить при сбое? (влияет на γ)
- Какой бюджет? (влияет на δ)

### 2. Базовые правила

| Параметр | Низкий (0.5) | Средний (1.0) | Высокий (1.5) | Очень высокий (2.0) |
|----------|--------------|---------------|---------------|---------------------|
| α (Quality) | Простые задачи | Стандартные задачи | Критичные задачи | Медицина, финансы |
| β (Speed) | Batch обработка | Обычные API | Chat, автодополнение | Gaming, trading |
| γ (Stability) | Есть retry логика | Стандарт | Production critical | 24/7 сервисы |
| δ (Cost) | Unlimited budget | Enterprise | Стартап | MVP, хобби проект |

## ⚖️ Нормализация весов

Иногда полезно нормализовать веса:
```python
def normalize_weights(weights):
    total = sum(weights.values())
    return {k: v/total for k, v in weights.items()}
```

Это гарантирует, что сумма всех весов = 1.0

## 📈 Продвинутые техники

### 1. Динамические веса
Веса могут зависеть от контекста:
- Дневное время: приоритет скорости
- Ночное время: приоритет качества (больше времени)

### 2. Multi-objective оптимизация
Используйте Pareto-оптимальность для поиска баланса

### 3. Machine Learning
Обучите модель предсказывать оптимальные веса на основе:
- Типа задачи
- Истории использования
- Feedback пользователей

## 🚨 Частые ошибки

1. **Слишком экстремальные веса** (0.1 или 3.0)
   - Делают формулу нестабильной
   
2. **Игнорирование стабильности** (γ < 0.5)
   - Приводит к выбору ненадежных моделей
   
3. **Недооценка стоимости** (δ < 0.5)
   - Быстро исчерпывает бюджет

4. **Все веса одинаковые** (1.0, 1.0, 1.0, 1.0)
   - Не отражает реальные приоритеты
